Python Class Pollution

A research wiki on a Python-specific variant of prototype pollution.

Class pollution is a vulnerability pattern in which an attacker uses Python's dunder attributes (__class__, __init__, __globals__, sys.modules, …) to traverse the runtime object graph and overwrite attributes in unintended classes, functions, or modules. It is the closest Python analogue to JavaScript prototype pollution, and it does not require the target program to import anything unusual — only to perform a reflective setattr/__setitem__ whose path comes from untrusted input.

Read the wiki · Paper (S&P 2025) · Source on GitHub

The shape of the bug

# A recursive update routine. Looks innocuous.
def update(user, data):
    for key in data:
        val = data[key]
        if isinstance(val, dict):
            update(getattr(user, key), val)
        else:
            setattr(user, key, val)

# Attacker-controlled input:
data = {"__class__": {"__getattribute__": "1337"}}

update(user, data)
# -> type(user).__getattribute__ = "1337"
# Any attribute access on any User instance now raises TypeError.

The loop resolves each key with getattr, which does not distinguish between a developer-defined attribute and a builtin dunder. A payload that steps through __class__ → __getattribute__ reaches the class object and overwrites a descriptor that is consulted on every attribute access.

This is a denial-of-service primitive. By continuing through __init__ → __globals__ → sys.modules, the same primitive reaches any imported module — os.environ, template engines, Django settings — which is what turns it into RCE, stored XSS, or authentication bypass.

What's in this wiki

Taxonomy
The six vulnerability types that arise from combining two "get" primitives (agnostic, constrained) with three "set" primitives (dual, attr, item). Only one of the six was previously documented.
Targets
What can be polluted in Python — classes, functions, modules — and the reflective paths that reach each one.
Gadgets
Reusable chains with concrete consequences: RCE through os.environ.BROWSER + antigravity, universal stored XSS through BeautifulSoup's entity map, DoS through __getattribute__, authentication bypass through Django's SECRET_KEY.
Collection
77+ real Python packages where Pyrl found class pollution sinks, with proof-of-concept code in cp-collection/. Deep-dive showcases for Azure CLI, Mesop, Taipy, and django-unicorn.
Tools
Pyrl — a CodeQL-based detector built around operational taint analysis. Polluter — a runtime library for enumerating pollutable paths on a live object and testing gadget chains.
Defense
Practical mitigations for library authors: forbidding dunder-prefixed keys at the sink, normalising the traversal path, and using typed data containers that do not expose setattr.
